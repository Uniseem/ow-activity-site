### Cloudflare

- 配置：`wrangler.jsonc`、`open-next.config.ts`、`.dev.vars.example`、`public/_headers`。
- 模型与迁移：`prisma/cloudflare/`。英雄数组以 JSON 存储；上传媒体使用 R2，D1 保存引用。
- 核心实现：`src/lib/cloudflare.ts`、`database-provider.ts`、`prisma.ts`、`d1-atomic.ts`、`asset-storage.ts`、`database-transfer.ts`、`oauth/d1-accounts.ts`。

- D1 不支持 Prisma 交互事务：通用客户端明确拒绝 `$transaction`，关键业务使用原生 D1 batch；不能用多次独立写入绕过。
- `scripts/cloudflare.mjs` 提供构建、预览、部署，并清空 OpenNext 自动复制的环境配置，避免把本地 Vercel 凭证打进包。

- 指南：`docs/Cloudflare部署.md`。

### VPS

- `Dockerfile`：Node 22 多阶段构建、迁移镜像、非 root standalone 运行镜像。
- `compose.yml`：PostgreSQL 17 持久卷、健康检查、迁移顺序、网站、每分钟日期同步、可选 Caddy HTTPS。
- `scripts/install.sh`：下载代码、生成密钥、保留现有配置与卷、更新失败中止，支持域名/目录/端口/自定义仓库。
- `deploy/` 包含配置模板、Caddy、scheduler、安装模拟测试和最终镜像 standalone 烟测脚本。
- 安装脚本已防止终端同名环境变量覆盖经校验的 Compose 配置。
- 指南：`docs/VPS部署.md`。脚本需要目标机已有 Docker Engine、Compose v2、git、curl、openssl，不自动安装系统组件。

### 后台备份与恢复（仍需重点收尾）

- 新增 `/admin/backup` 页面、导航入口、`BackupManager`、`/api/admin/backup`。
- 新增 `backup-format.ts`、`backup-service.ts`、`backup-zip.ts`。
- PostgreSQL 新迁移 `20260906030000_site_backup` 增加 `BackupTransfer` / `BackupChunk`，D1 模型同步。
- ZIP 格式为 `data.json` 元数据加 `media/<id>.bin`；元数据上限 8 MiB、媒体总量 128 MiB、单图 2 MiB、最多 5,000 张图片及 50,000 条记录。
- HTTP 按 384 KiB 原始数据分块，避开 Vercel 单次请求大小限制；服务端逐张处理媒体。
- 原头像 data URL 在备份时提取为媒体，恢复后的资料指向站内图片接口。
- PostgreSQL 使用一致性快照与事务覆盖；D1 先写新的不可变 R2 对象，再 batch 原子切换全部记录与图片引用。
- ZIP 保存密码哈希与 OAuth 绑定；源站加密配置先解密，恢复时用目标站的 `OAUTH_ENCRYPTION_KEY` 重新加密。
- 不迁移登录会话与 OAuth 临时 state，恢复后所有人重新登录；目标站域名和环境变量保留。
- 外链图片保留原地址，不下载外链；ZIP 不包含代码、数据库连接密码和宿主环境配置。
- ZIP 含敏感账号信息和 OAuth 应用密钥，不应公开提交或分享。

## 已在本轮收尾

1. **备份协议与容量边界。** API、客户端和 ZIP 解析器共用媒体分离格式。分块上限改为按 8 MiB 元数据 + 最多 5,000 张小图计算（`BACKUP_MAX_CHUNKS`），清单请求上限 2 MiB，单块 Base64 上限与 384 KiB 对齐。
2. **真实外键与审计字段。** 只强制 `userId` / `authorId` / `createdById` / `reviewedById` 以及报名对应活动；`updatedById` / `uploadedById` 允许指向已删账号。
3. **备份测试和说明。** 已补文档与单测；集成测试用 `BACKUP_TEST_DATABASE_URL` 的独立临时 schema，覆盖大于 4.5 MB ZIP、跨密钥、旧密码、目标账号消失、会话清除、图片、损坏文件、失败回滚和权限/Origin。
4. **构建入口。** 普通 Next 构建不再静态打包 D1 wasm。
5. **更新提醒缓存。** 业务上以缓存载荷里的 UTC ISO 时间为准；`getUpdateSettings` 改为查找后创建。并发检查在租约释放后会再读一次缓存，避免后到的请求把同一次检查再打一遍 GitHub。
