# 文章功能说明

管理员打开后台的“文章管理”（`/admin/articles`），点击“写文章”。文章标题必填，正文可以先留空保存草稿；完成后点击“发布文章”，文章就会出现在前台文章列表。首页的最新文章栏突出首篇，其余文章紧凑排列。

## 发布与编辑反馈

编辑页顶部固定显示文章状态和常用操作。发布成功后状态变为“已发布”，显示发布时间，并提供“查看文章”；再次修改时标记“有未保存修改”，出现“更新文章”按钮。保存、发布、更新、撤回和失败结果都显示在操作区。

文章封面位于标题下方，可直接上传、更换、填写链接或移除，并显示预览。前台文章卡片以封面铺底，标题、摘要和作者日期置于中央圆角液态玻璃面板；没有封面或图片加载失败时使用普通 HeroUI 卡片，不放图片占位。不支持背景模糊或偏好减少透明度时，文字面板使用实色表面。

摘要单独收起，留空时从正文提取。Markdown 导入导出、撤回和删除放在“更多”菜单；工具栏只展示常用格式，其余在“更多格式工具”中展开。确认删除后返回文章列表，并显示删除成功提示。

未保存正文在当前浏览器标签页保留临时备份，按管理员与文章区分，24 小时后过期。重新进入时需明确选择恢复或丢弃；新稿恢复会先检查是否已保存，避免重复创建。备份不代替服务端保存，存储不可用时会提示。

保存时如果登录过期，页面保留正文，提示在新标签页重新登录后重试。刷新、点击站内链接或退出登录时，对未保存修改给出离开提示；浏览器后退后可以通过临时备份恢复内容。

## 编辑器选型

调研了以下开源方案，最终使用 Tiptap 3，外层操作界面继续使用 HeroUI。

| 方案 | 适合的场景 | 本站选择 |
| --- | --- | --- |
| [Tiptap](https://tiptap.dev/docs/editor/getting-started/install/nextjs) | 通过扩展组合富文本编辑功能，可自行设计工具栏 | 富文本为主，同时需要 Markdown，适合接入现有 HeroUI 后台 |
| [Milkdown](https://milkdown.dev/docs/guide/why-milkdown) | Markdown 为核心的所见即所得编辑 | 可作为 Markdown 优先的选择 |
| [Lexical](https://lexical.dev/docs/intro) | 可扩展的编辑器框架 | 完整工具栏和编辑体验需要更多自行组合 |

[Tiptap 核心采用 MIT 许可证](https://github.com/ueberdosis/tiptap/blob/main/LICENSE.md)。本站使用其开源编辑扩展，没有接入收费云服务。前台使用 [react-markdown](https://github.com/remarkjs/react-markdown) 与 remark-gfm 安全渲染 Markdown。

## 已接入能力

- 富文本、Markdown 源码、阅读预览三种模式；Markdown 快捷输入。
- 粗体、斜体、删除线、标题、普通列表、任务列表、引用、代码块、分隔线、链接、图片和表格。
- 图片可填写地址，也可上传 PNG/JPEG/WebP/GIF，单张最大 2 MB；文章封面也支持上传。上传复用已受管理员权限保护的站点图片服务。
- Markdown 文件导入与导出；导入会先确认覆盖正文。
- 标题、摘要与封面独立编辑。摘要留空时提取正文；标题最多 120 字，摘要最多 300 字，正文最多 10 万字符。
- 保存草稿、发布、更新已发布文章、撤回、删除。撤回和删除需确认；文章列表可按状态筛选和按标题搜索。
- 保存失败保留当前内容；多人同时编辑通过版本号检测冲突，防止静默覆盖。刷新或点击其他页面链接时提示未保存修改。
- 前台支持文章列表、标题及摘要搜索、分页、文章详情和首页最新文章入口。

[官方 Markdown 扩展仍标注为 Beta](https://tiptap.dev/docs/editor/markdown)。本站锁定 Tiptap 版本为 3.31.3，并验证常用 Markdown 在富文本解析、导出、前台渲染之间保留。原始 HTML 不作为文章格式执行；Markdown 不支持的复杂排版不提供工具按钮。表格单元格限定为单段落，避免导出 Markdown 时丢失多段落内容。复杂外部文档导入后应检查阅读预览，源码模式可保留和修改 Markdown 文本。

## 数据与权限

新增 `Article` 表和 `ArticleStatus` 枚举。文章保存为 Markdown，记录作者、封面、摘要、首次发布时间、更新时间与修订号。

- 所有管理页面及保存、删除、图片上传操作都在服务端检查管理员权限。
- 前台查询仅允许 `PUBLISHED` 且存在发布时间的文章。草稿或已撤回文章的详情、搜索、首页入口均不可公开访问，页面元数据也不泄露草稿内容。
- 页面不执行原始 HTML，链接和图片过滤危险协议；外链使用 `noopener noreferrer`。
- 图片继续存入 Neon 中的 `SiteAsset`，通过原有公开只读图片接口提供，不需要新增云存储账号。删除文章不会自动删除可能被其他文章引用的图片。

部署时需应用迁移 `20260905220000_articles`。执行 `npm run db:deploy`；项目的 Vercel 构建命令已包含该步骤。升级不会插入示例文章或改动现有管理员。

## 验证

`npm test` 包含正文校验、危险 URL 与 HTML 过滤、常见 Markdown 往返测试。设置 `ARTICLE_TEST_DATABASE_URL` 后运行 `npm run test:articles`，在独立临时 schema 中验证管理员权限、草稿隔离、发布撤回、并发修改和删除，完成后清理测试 schema。

本地浏览器验证涵盖富文本输入、Markdown 切换、图片地址插入、封面设置、保存、发布、前台阅读、撤回和删除，以及手机布局。检查命令为 `npm run lint`、`npm run typecheck`、`npm run build`。
