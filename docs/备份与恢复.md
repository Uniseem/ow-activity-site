# 备份与恢复

管理员打开后台「备份与恢复」（`/admin/backup`），可以下载完整网站 ZIP，或把旧站导出的 ZIP 覆盖导入到当前站点。适用于 Vercel、Cloudflare 和 VPS 之间迁移，也适用于换机重建。

ZIP 含账号、密码哈希、第三方账号绑定、玩家资料、活动、报名、文章、站点设置、OAuth 应用密钥、Deploy Hook 和已上传图片。不要公开提交或分享。登录会话和 OAuth 临时 state 不在备份内；恢复后所有人重新登录。目标站的域名、环境变量和 `OAUTH_ENCRYPTION_KEY` 保持不变。

## 下载

点击「下载完整 ZIP」。服务端先冻结一份一致性快照，再按 384 KiB 分块传回浏览器，由浏览器组装 ZIP。进度条按分块计算。下载完成后临时传输记录会删除；未完成的任务 30 分钟后过期。

旧式头像若仍以 data URL 存在资料里，导出会抽成独立图片，恢复后的资料指向 `/api/site-assets/...`。外链图片保留原地址，不会改写为站内文件。代码、数据库连接密码和宿主配置不在 ZIP 内。

## 导入与覆盖恢复

1. 选择 ZIP。浏览器先检查文件尾、路径和清单，再分块上传。
2. 服务端校验元数据、真实外键、图片格式和校验和，并显示账号、文章、活动、报名和图片数量。
3. 输入「覆盖恢复」确认。当前站点的账号、内容和图片会被备份整表替换。
4. 恢复成功后退出登录，使用备份中的管理员用户名和原密码重新登录。

请求必须来自站点自己的 Origin。未登录、非管理员或来源不匹配会直接拒绝，不会开始恢复。

## 容量与分块

| 限制 | 数值 |
| --- | --- |
| 元数据 | 8 MiB，最多 50,000 条记录 |
| 图片总量 | 128 MiB |
| 单张图片 | 2 MiB |
| 图片数量 | 最多 5,000 张 |
| 分块 | 每块 384 KiB 原始数据 |
| 单次 JSON 请求 | 2 MiB |

超过任一上限会停止并提示，不会省略内容或生成不完整 ZIP。5,000 张小图时，分块序号按「每张至少一块 + `data.json` 的额外块」计算，API 允许的最大序号与该上界一致。清单本身（含 5,000 条媒体记录）小于 2 MiB，可放在一次导入请求里。

## 外键与审计字段

备份必须带齐真实外键：`userId`、`authorId`、`createdById`、`reviewedById` 以及报名对应的活动。缺少这些记录会被拒绝。

`updatedById` 和 `uploadedById` 没有数据库外键，只记录当时操作的人。账号删除后这些字段可能指向已不存在的用户，合法备份仍可导入。

## 密钥与跨平台

源站导出时用自己的 `OAUTH_ENCRYPTION_KEY` 解密 OAuth 客户端密钥和 Deploy Hook，明文只存在这份 ZIP 里。目标站导入时用自己的密钥重新加密。更换密钥后，只要 ZIP 还在，仍可用新密钥恢复。未配置密钥的目标站无法导入含密钥的备份。

PostgreSQL 部署用事务覆盖：先锁表、删除业务表、再写入备份。任一步失败都会回滚，不会留下删了一半的站点。Cloudflare 部署先把图片写入新的不可变 R2 对象，再用 D1 batch 一次切换全部记录和引用；失败时删除这批尚未切换的 R2 对象，现有数据不变。

支持 PostgreSQL 与 D1 互迁。D1 的图片在 R2，PostgreSQL 的图片在数据库字节列；ZIP 只保存媒体文件，不保存任何一方的内部存储键。

## 恢复后还要做的

- 用备份中的管理员账号登录。
- 域名若已更换，到「第三方登录」更新 Google / GitHub 回调地址。
- Deploy Hook 只适用于 Vercel，监测其他仓库时需重新填写。
- 活动日期仍按上海时间计算；无人访问的 Cloudflare 部署不会单独跑日期同步定时任务。

## 校验

`npm test` 覆盖清单容量、外键与审计字段、大于 4.5 MB 的 ZIP 往返、损坏文件和 CSRF Origin 判断。设置 `BACKUP_TEST_DATABASE_URL` 后运行 `npm run test:backup`，在独立临时 schema 中验证跨密钥恢复、旧密码登录、目标账号消失、会话清除、图片一致、权限拒绝和失败回滚。不要把该 URL 指到正在使用的网站数据库。
